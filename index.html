Uptime monitoring you configure with code

Jammonic watches your sites, ports, certificates and cron jobs, shows a public status page and tells you when something breaks. Everything you can click in the UI, you can also do with one REST call or one YAML file.

What it watches

Four kinds of checks cover a typical small infrastructure.

HTTP(S)

Status code, a word on the page, response time. "Down" only on 5xx if you like — redirects and logins stay green.

TCP

Any port: database, SMTP, SSH, game server. Up when the port answers.

Certificates

The full TLS chain, like a browser checks it, and a warning days before expiry.

Push

Backups, cron jobs, timers call a URL when done. No signal in time — it's down.

Public status page

Groups, 90 days of uptime bars, rendered on the server: fast, readable without JavaScript.

Alerts

Telegram, email and a signed webhook. A short blip is re-checked before it becomes an alert.

Small and fast

Java 25 with an AOT cache starts in seconds; one container, SQLite in a volume, backup = copy one file.

Modern Spring

Spring Boot 4, Spring Modulith, virtual threads, Angular 22 — open, readable code to learn from.

Monitoring as code

Your deploy script adds a check; your backup script reports in. Idempotent by your own key — run it twice, nothing doubles.

REST API

# create or update by your key
curl -X PUT -H "X-Api-Key: $KEY" \
  -H 'Content-Type: application/json' \
  -d '{"name":"shop","type":"HTTP",
       "target":"https://shop.example.com"}' \
  $JAMMONIC/api/v1/checks/by-external-id/shop-web

# at the end of a backup — no key needed
curl -fsS $JAMMONIC/push/<token>

One YAML file

checks:
  shop-web:
    name: shop
    type: http
    target: https://shop.example.com
    status-page: true
  nightly-backup:
    name: Nightly backup
    type: push
    interval-seconds: 86400
    grace-seconds: 3600
