Changelog

0.5.0 — 2026-11-26

  • The YAML configuration file is back, now with groups: groups (status page, order, owner) and checks in one file set by MONITOR_CONFIG_FILE, applied at every start. See Configuration file.

0.4.0 — 2026-11-26

  • Demo mode (MONITOR_DEMO=true) — try it at demo.jammonic.com: a shared sign-in, read-only built-in checks, your own checks in "Playground", everything visitors add is removed at night.
  • MONITOR_PUBLIC_TARGETS_ONLY=true: only public addresses are checked — no private networks, loopback or link-local, the address is checked before every probe and HTTP does not follow redirects.

0.3.4 — 2026-11-24

  • Groups have an order: lists and the status page follow it.

0.3.3 — 2026-11-24

  • Groups named after environments come first: Dev, Staging, Production, then the rest.

0.3.2 — 2026-11-22

  • Passwords need at least 8 characters (was 10).

0.3.1 — 2026-11-22

  • Status page periods: 24 hours, 7 days (by hour), 90 days (by day). Click a check to see response time and outages.

0.3.0 — 2026-11-22

  • Groups belong to a user; forms for groups and checks; every user can open their own status page /status/<username> for the groups they mark public. The configuration file was removed in this version (back in 0.5.0).

0.2.1 — 2026-11-22

  • Alerts per group: own email recipients, the group's members and a Telegram chat. See Alerts.

0.2.0 — 2026-11-22

  • Sign in with a username and password; users and groups of checks. See Sign-in.

0.1.8 — 2026-11-20

  • Webhooks through the API and a "managed by" label that shows which program keeps a check.

0.1.7 — 2026-11-19

  • Email only for the checks you choose: MONITOR_MAIL_TYPES=PUSH sends letters about backups and timers, while Telegram keeps reporting everything. Empty — email about all checks, as before. See Alerts.

0.1.6 — 2026-11-19

  • Moving from Uptime Kuma without touching your scripts: push checks also answer at /api/push/<token> — the same address Kuma uses — and a PUSH check can be created with your own pushToken, so the old token keeps working. See Moving from Uptime Kuma.

0.1.5 — 2026-11-19

  • Status page on its own domain: list it in MONITOR_STATUS_HOSTS (e.g. status.example.com) and the root of that domain opens the status page at once; other domains still open the app. See Status page.
  • Favicon made from the logo.

0.1.4 — 2026-11-19

  • Status page: a heart monitor line above the uptime bars — a green day beats, a red day is a flat line, a bright sweep runs across. Light theme looks like a bedside monitor, dark theme like a green oscilloscope.
  • Theme switch: Auto / Light / Dark, in the app header and at the bottom of the status page; remembered in the browser.
  • Smoother scrolling on the status page: the trace is drawn once and only the sweep moves.

0.1.3 — 2026-11-18

  • New look: a slowly moving glow and a faint grid instead of the background picture, a beating pulse in the logo, breathing status dots (a down check pulses red); motion is off when the system asks for reduced motion.

0.1.2 — 2026-11-18

  • Frosted-glass cards and header.

0.1.1 — 2026-11-18

  • License: free for any use, including commercial; the source code is not published. The text is in the image, /app/licenses/LICENSE — see License.

0.1.0 — 2026-11-18

First public image.

  • HTTP(S), TCP, certificate and push checks; repeat before DOWN.
  • REST API with idempotent create-or-update by your key; YAML configuration file.
  • Public status page rendered on the server.
  • Alerts: Telegram, email, signed webhook.
  • Web UI (Angular 22); sign-in with an API key or with Jambotron.
  • Spring Boot 4.1, Java 25 with an AOT cache, SQLite.
